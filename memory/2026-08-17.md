**Probe design lesson:** the 2026-08-16 and first 2026-08-17 probes printed only
a summary line at the end, so a hang produced an EMPTY output -- byte-identical
to "ssh failed" or "command not found". Any filesystem-health probe must print
per-file with `python3 -u` so a hang yields partial data that localises it.
Re-probing the same paths is also invalid; caching makes a sick filesystem look
well. Always sample fresh random paths.

**Design consequence:** a signal-based watchdog CANNOT kill a D-state filesystem
hang. The progress watchdog still covers every interruptible stall (NCCL
deadlock, dataloader race, livelock), but for THIS fault the only real defence
is the preflight, which runs before any GPU work while the process is still
killable. Documented at the watchdog's kill site.

Fault has persisted ~2 days (since ~2026-08-15). Warrants an RC ticket.

## Preflight now REQUEUES instead of dying

An unreadable filesystem is a transient infrastructure fault, not a verdict on
the experiment. Dying wastes the ~6h queue wait and needs a human to notice;
waiting in place holds 4 GPUs idle, the exact failure the preflight prevents.
So: `scontrol requeue` + `StartTime=now+45minutes`, bounded to 8 attempts via
`SLURM_RESTART_COUNT`. **Requires `#SBATCH --requeue`** -- without it SLURM
refuses the requeue and the whole path silently degrades to a plain exit.
