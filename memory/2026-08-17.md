## SSH restored; holylfs06 partially recovered but NOT healthy

Cluster SSH works again. Queue empty, `active_runs` empty.

The three specific JPEGs that hung on 2026-08-16 now read in 0.05s -- but that is
**not** evidence of recovery, it is almost certainly client/OSS cache from the
2026-08-16 probe itself. A *random* 120-file sample across 40 classes did not
complete within a 90s timeout, when the measured median read (0.05s) predicts
~6s. So the intermittent-hang fault persists: most files are fast, a subset
blocks indefinitely.

**Probe design lesson:** the 2026-08-16 and first 2026-08-17 probes printed only
a summary line at the end, so a hang produced an EMPTY output -- byte-identical
to "ssh failed" or "command not found". Any filesystem-health probe must print
per-file with `python3 -u` so a hang yields partial data that localises it.
Re-probing the same paths is also invalid; caching makes a sick filesystem look
well. Always sample fresh random paths.

## Three II-C launcher defects fixed (all silent-failure class)

`experiments/btm/launch_image_phase.py`:

1. **IIC `save_epochs` was "1,2,5,10,20,40,80"** -- jumps 40 -> 80 and so places
   NO checkpoint anywhere in the epoch-55 onset band. A run that crossed the
   transition would have left no artifact of it. Now epochs=60 sampled
   20,30,40,50,55,60.
2. **`--tc` was free on a phase that resumes from tc=0.9 checkpoints.** II-B ran
   at tc=0.9 (recovered from its log.txt: `BTMConfig(... tc=0.9, kappa=0.8 ...)`),
   and my own first dry-run used 0.8. Changing tc at a resume boundary changes
   the regression target mid-trajectory while the loss stays finite and the
   curve stays smooth on both sides. Now asserted against `resume_tc`.
3. **Dry runs appended `status="planned"` rows to the experiment manifest**, so
   merely inspecting a phase left rows indistinguishable by position from real
   submissions. Dry run now returns before `record()`.

Also added `resume_from` (each arm continues from its OWN II-B epoch15 weights,
so II-C and II-B read as one curve) and `--job-name` so `%x` resolves.

Note the launcher passes env as `VAR=val ... sbatch`, i.e. through the SHELL
environment -- so it was never exposed to the `--export` comma-split bug. That
bug was in the hand-rolled resubmit only.
