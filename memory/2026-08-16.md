# 2026-08-16

## Phase II-C hung for 35.5h -- root-caused to the diagnostic probe's second worker pool

Both II-C jobs (39216096 V, 39216098 G, launched Aug 14 22:33/23:40) made ZERO
training steps in 35.5h on 8 A100s. Not slow IO -- a deadlock:

- `py-spy dump` on rank 0: MainThread parked in
  `_try_get_data (dataloader.py:1132)` <- `__next__` <- **`train.py:384`**,
  i.e. `_probe_x, _probe_y_raw = next(iter(loader))`.
- All ~32 dataloader workers in state `I (idle)`, `wchan == 0`, **no `D` state
  anywhere** -- so nobody was blocked in filesystem IO. Rules out the known
  holylfs06 ~27-files/s starvation story.
- Workers still held open ImageNet JPEG fds *opened Aug 15 19:23* -- ~15h after
  job start. So the pool ran, prefetched until its queue filled, and wedged;
  the main process never received batch #0.
- `py-spy dump` on a worker hangs hard enough to drop the ssh connection.

**Mechanism.** `next(iter(loader))` builds a SECOND
`_MultiProcessingDataLoaderIter` -- a full `num_workers` pool per rank (32
processes at 4x8) plus a pin_memory thread -- to fetch ONE batch, then abandons
it. Teardown happens only via refcount `__del__`/`_shutdown_workers`, racing the
epoch loop's own pool on the same mount.

**Fix (invariant, not patch): at most one multiprocess worker pool live per
rank.** Probe batch now comes from a `num_workers=0` DataLoader over the same
dataset and the SAME sampler -- bit-identical images, since
`DistributedSampler.__iter__` is a pure function of (epoch, seed, rank) and
holds no cursor. Global RNG state snapshotted/restored across the fetch so the
construction is provably side-effect-free on the training stream. Cost: one
serial read of `local_batch_size` JPEGs.

Note this line was present in II-A/II-B too and did not fire -- it is a race,
which is exactly why removing the second pool (rather than retrying) is the fix.

## CORRECTION to the deadlock diagnosis above: the real blocker is holylfs06

The `next(iter(loader))` double-worker-pool finding is real and the fix is kept,
but it is NOT what stopped Phase II-C. After the fix, the relaunched jobs
(39567834 V, 39567835 G, GIT_SHA 537ac3e) stalled at the SAME place with a
`num_workers=0` probe and no worker pool at all.

`/proc/<rank>/syscall` = **5** (`fstat`) on fd 89 -> an ImageNet JPEG on
`/n/holylfs06` (lustre). Evidence:

- `ls` of the 1000-class train root: instant. `stat` of the root: instant.
- `lfs df`: all 33 OSTs present, active, 72-75% used. Nothing marked inactive.
- Reading a SINGLE JPEG: `timeout 20 dd` -> TIMEOUT.
- Sampled reads: 0.08s, 0.04s, 1.62s, then indefinite hang. So most files are
  fast and **a subset blocks forever** -- not uniform congestion.

So II-A/II-B (Aug 13-14) trained at 4.5 steps/s on this exact path; the fault
appeared afterwards. Four II-C job-attempts, ~38 A100-hours, zero training steps.

**Load-bearing gotcha found while resubmitting:** SLURM `--export=ALL,K=V,...`
SPLITS ON COMMAS, so `SAVE_EPOCHS=20,30,40,50,55,60` silently becomes
`SAVE_EPOCHS=20` and the epoch-55/60 checkpoints -- the entire point of II-C,
which exists to cross the ~epoch-55 CV-explosion onset -- would never be
written. Export multi-value vars through the environment and pass `--export=ALL`.

## Two real bugs found in analyze_image_v2.py while trying to use it

1. **Verdict conflated "selector matched nothing" with "everything was rejected."**
   `--phase II` selects zero runs (the specs carry phase `IIA`), and the report
   said *"Every selected run failed the completeness gate; see 'quarantined' for
   why"* with an EMPTY quarantine list -- sending the reader to audit data quality
   for a run set that was never looked at. Now reports NO RUNS SELECTED with the
   selector echoed.
2. **The exit-code guard never fired.** It was a denylist matched via
   `verdict.split(":")[0]`, but the sentinels it listed are followed by ". ", not
   ":", so `NO ANALYZABLE RUNS` split to the whole string and matched nothing --
   `rc=0`. `NOT COMPARABLE:` was never in the list at all. So a pipeline could
   consume an empty or confounded report and proceed, which is precisely what the
   guard existed to prevent. Replaced the denylist with the complement of the
   single success sentinel (`rc=0 iff verdict startswith "OK"`), which fails
   closed for verdicts added later. 55 tests pass.
